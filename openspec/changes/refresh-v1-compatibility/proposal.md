# Refresh the V1 compatibility baseline

## Why

Before porting the sidebar to OpenCode 2, establish a verified baseline on the latest OpenCode 1.x and OpenSpec releases. The checkout currently resolves the OpenCode SDK to 1.18.4 and carries OpenSpec instructions generated by 1.8.0.

## What Changes

- Update the development SDK to OpenCode 1.19.4 and declare the supported OpenCode 1.x range explicitly.
- Regenerate the repository's OpenCode commands and skills with OpenSpec 1.14.3.
- Pin the OpenSpec development CLI and OpenTUI renderer used for reproducible compatibility checks.
- Check the parser and tooling detection against a project generated by the actual OpenSpec CLI.
- Align task progress with OpenSpec 1.14.3, including nested and ordered tasks, padded or empty checkboxes, and unfinished markers.
- Show nested task hierarchy, ordered labels, and unfinished markers in the TUI, with useful empty-task states and a review reminder when all tasks are checked.
- Prepare version 1.0.0 for OpenCode V1 with release notes for task progress and the expanded task view. Reserve plugin 2.0.0 for OpenCode V2.
- Document the verified versions and the separate V2 migration boundary.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `openspec-parsing`: Task counts and completion markers follow the current OpenSpec CLI semantics.
- `change-tracking-ui`: Task details retain hierarchy and markers, and explain empty or fully checked task lists.

## Non-goals

- Porting to the OpenCode 2 plugin or server APIs.
- Replacing the machine's OpenCode 2 installation.
- Adding OpenSpec store/profile features to the sidebar.
- Changing main specs, publishing a release, or committing existing work.

## Impact

Task parsing in `src/lib/openspec.ts`, release notes, package metadata and lockfile, generated `.opencode` tooling, compatibility tests, and README. Preserve the pre-existing primitive-component refactor, lint configuration, CI checks, and tests.
